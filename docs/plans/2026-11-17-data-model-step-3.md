# Data model step 3 implementation plan

> **For Claude:** REQUIRED SUB-SKILL: Use superpowers:executing-plans (or subagent-driven-development in this session) to implement this plan task-by-task.

**Goal:** The property holds what is true about the yard (zones, controller, backflow, gate code, must be home, access note, on-site contact, notes), the customer holds the card on file, and the job holds what makes it a Season Pass (season, pass number, the job it renews). After this step nothing on `season_pass` is the only copy of anything; step 6 drops the table.

**Architecture:** Three migrations, each adding columns and backfilling them from `season_pass`, then the writers write the new home and the readers read it. `season_pass` keeps being written as an alias for one season (its ids are the `passes.*` API ids, the Stripe metadata, the queue payloads and the `pass_id` foreign keys), exactly as `visit.truck_id` and `job.price` were kept in steps 1 and 2. States stay derived. Every field touched gets its row in `docs/DATA_MODEL.md` in the same commit. One PR, `step-3-property-card-job`, branched from `origin/main` at or after `98c423a`.

**Tech Stack:** Next.js 16 App Router, Drizzle on Neon (migrations in `drizzle/` generated by `npx drizzle-kit generate --name <name>`, then edited by hand for the backfill; applied by `scripts/db-migrate-on-build.mjs` on deploy), vitest with pglite (`src/db/test-db.ts`, `src/api/test-helpers.ts`), zod handlers in `src/api/v1/*` registered in `src/api/v1/index.ts`, Storybook with axe, the design gate in `npm run lint`.

Design: `docs/plans/2026-11-16-data-model-design.md` (the records table and "The Season Pass on this model"). Read it first, then `docs/DATA_MODEL.md`, `docs/DESIGN.md`, `docs/UX_WRITING.md`, and the step 1 and 2 plan `docs/plans/2026-11-16-data-model-steps-1-2.md` for the conventions.

**Rules that hold for every task**

- A pushed branch migrates and seeds the production database at once (Preview and Production share `DATABASE_URL`). The branch is pushed only when the whole step is done, and a migration is never edited after its commit is pushed.
- Every backfill is idempotent (`where <new column> is null`) and every seed insert is safe on a migrated database with real rows (`src/db/seed.ts` upserts by id and never overwrites a column the office may have edited).
- Old columns stop being the source of truth but keep being written where a write is cheap, so a rollback of the code (not the schema) still works for one deploy. They are listed in `docs/DATA_MODEL.md` as "legacy until step 6".
- Commit messages are one plain sentence ending with the line `Co-Authored-By: Claude Fable 5.1 <noreply@anthropic.com>`; `npx tsc --noEmit` and `npx vitest run --project unit` before every commit; new handler tests follow `src/api/v1/trucks/handlers.test.ts` (`apiDb()`, `ctxFor(db, adminKey)`). Words on screen: sentence case, no em dashes, the words in `docs/UX_WRITING.md`.
- Implementers never touch `drizzle/` except in the task that generates that task's migration, and never push.

**Step 3: Add the columns** to `property` in `src/db/schema.ts`, after `lng`/`geocodedAt`:

```ts
    /** the yard: filled by the checkout's zones step, the office, or the backfill from the newest pass */
    zones: integer("zones"),
    controller: text("controller"),
    backflowLocation: text("backflow_location"),
    gateCode: text("gate_code"),
    mustBeHome: boolean("must_be_home").notNull().default(false),
    accessNote: text("access_note"),
    contactName: text("contact_name"),
    contactPhone: text("contact_phone"),
    notes: text("notes"),
```

Generate: `npx drizzle-kit generate --name property_fields` → `drizzle/0015_property_fields.sql`. Append the backfill by hand (newest pass per property, active first):

```sql
update "property" p
set "zones" = sp."zones", "must_be_home" = sp."needs_customer_home", "access_note" = sp."access_note"
from (
  select distinct on ("property_id") "property_id", "zones", "needs_customer_home", "access_note"
  from "season_pass"
  order by "property_id", ("status" = 'active') desc, "created_at" desc
) sp
where sp."property_id" = p."id" and p."zones" is null;
```

Run `npx drizzle-kit check` and `npx vitest run --project unit src/db` (the pglite test DB applies every migration, so the backfill SQL is exercised).

**Step 4: Seed.** In `src/db/seed.ts` the property insert carries `zones: pass.zones, mustBeHome: pass.needsCustomerHome ?? false, accessNote: pass.accessNote ?? null` with `onConflictDoNothing` (never an update: the office may have edited the yard). `src/db/seed.test.ts`: a seeded property has the snapshot's zones; seeding twice after an office edit keeps the edit.
