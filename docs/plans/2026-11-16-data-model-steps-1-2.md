# Data model steps 1 and 2 implementation plan

> **For Claude:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task.

**Goal:** Visits are assigned to a person instead of a truck (step 1), and every job is made of line items priced from a service catalogue that carries what each visit includes, sold from one New job sheet (step 2).

**Architecture:** Each step is one migration plus the code that reads and writes the new rows, shipped as its own PR on a branch from `origin/main` after PR #38 (office pass sale) and #39 (address) are merged. Old columns (`visit.truck_id`, `job.price`, `job.kind`) stay in place and stop being written; step 6 drops them. The API keeps `trucks.*` and `truckId` as aliases for one season. States stay derived; no new status columns. Every field touched gets its row in `docs/DATA_MODEL.md` in the same commit.

**Tech Stack:** Next.js 16 App Router, Drizzle on Neon (migrations in `drizzle/` generated by `npx drizzle-kit generate`, applied by `scripts/db-migrate-on-build.mjs` on deploy), vitest with pglite (`src/db/test-db.ts`, `src/api/test-helpers.ts`), zod handlers in `src/api/v1/*` registered in `src/api/v1/index.ts`, Storybook with axe, the design gate in `npm run lint`.

Design: `docs/plans/2026-11-16-data-model-design.md`. Read it first, then `docs/DATA_MODEL.md`, `docs/DESIGN.md`, `docs/UX_WRITING.md`.

Conventions for every task: commit messages are one plain sentence ending with the line `Co-Authored-By: Claude Fable 5.1 <noreply@anthropic.com>`; run `npx tsc --noEmit` before every commit; new handler tests follow `src/api/v1/trucks/handlers.test.ts` (`apiDb()`, `ctxFor(db, adminKey)`); the migration SQL is generated, then read and edited by hand for the backfill. Words on screen: sentence case, no em dashes.

```ts
/** A person who works here: the owner, a manager or a tech. Visits are assigned to a person; the truck is a label on them. An email makes them able to sign in. */
export const person = pgTable(
  "person",
  {
    id: id(),
    organizationId: orgId(),
    name: text("name").notNull(),
    initials: text("initials").notNull(),
    email: text("email"),
    phone: text("phone"),
    role: adminRoleEnum("role").notNull().default("tech"),
    /** the truck they usually drive, as a label: "Truck 1" */
    truck: text("truck"),
    jobberUserId: text("jobber_user_id"),
    /** their Jobber calendar subscription (iCal) URL; private, never returned by the API */
    calendarFeedUrl: text("calendar_feed_url"),
    workingDays: jsonb("working_days").$type<Weekday[]>().notNull().default(["mon", "tue", "wed", "thu", "fri"]),
    capacityByKind: jsonb("capacity_by_kind").$type<Record<CapacityKind, number>>().notNull().default({ "turn-on": 8, inspection: 8, blowout: 10, repair: 4, other: 2 }),
    seasonStart: text("season_start"),
    seasonEnd: text("season_end"),
    active: boolean("active").notNull().default(true),
    /** the truck row this person was made from by the step 1 migration; dropped in step 6 */
    legacyTruckId: text("legacy_truck_id"),
    createdAt: createdAt(),
    updatedAt: updatedAt(),
  },
  (t) => [index("person_org_idx").on(t.organizationId), uniqueIndex("person_org_email_unique").on(t.organizationId, t.email).where(sql`${t.email} is not null`)],
)
```

Add `personId: text("person_id").references(() => person.id)` to `visit` beside `truckId`, and an index `visit_person_day_idx` on `(personId, scheduledOn)`.

```ts
/** What a job is made of: one row per sold line, copied from the service at sale so a later catalogue edit never rewrites an old job. A pass line names the visit it is billed after. */
export const lineItem = pgTable(
  "line_item",
  {
    id: id(),
    organizationId: orgId(),
    jobId: text("job_id").notNull().references(() => job.id),
    serviceId: text("service_id").references(() => service.id),
    visitId: text("visit_id").references(() => visit.id),
    name: text("name").notNull(),
    description: text("description"),
    quantity: integer("quantity").notNull().default(1),
    /** whole dollars */
    unitPrice: integer("unit_price").notNull(),
    taxable: boolean("taxable").notNull().default(false),
    cancelledAt: ts("cancelled_at"),
    createdAt: createdAt(),
    updatedAt: updatedAt(),
  },
  (t) => [index("line_item_job_idx").on(t.jobId), index("line_item_visit_idx").on(t.visitId)],
)
```

Backfill SQL (appended to the generated migration): one line per visit of a pass job (`name` from the kind: 'Spring turn-on', 'Mid-season inspection', 'Fall blowout'; `unit_price = visit.amount`; `visit_id = visit.id`; `cancelled_at` copied when the visit is cancelled or skipped) and one line per one-off job (`name` from `job.kind`: 'Repair', 'Installation', 'Other'; `unit_price = coalesce(job.price, 0)`; `visit_id` = its first visit).
